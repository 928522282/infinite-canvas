# 脚本人物资产关联审核

## 目标

在任何人物生图或视频生成前，建立可追溯的“脚本提及 -> 规范人物 -> 确认资产 -> 出图单元白名单”。文件名只用于定位文件，不能单独证明人物身份。审核结果不是相似度推荐；只允许 `PASS` 或阻断生成的 `BLOCK`。

## 输入

尽可能完整读取：

- 原始文案、剧本、分镜表、台词和人物小传；
- 人物图片资产目录及现有资产表；
- 用户已确认的人名、别名、关系称谓和角色图；
- 待生成的场景、镜头、VID 或其他最小出图单元。

若输入是大型 CSV/XLSX/PDF，先用适合该格式的读取或预处理能力完整提取，保留原行号、镜头号、页码或单元格作为 `source_ref`。不得只读文件预览或抽样。

## 强制原则

1. **不信文件名**：文件名相似、包含人名或目录相邻均不是身份确认依据。
2. **不靠模糊抓取**：下游不得用人名搜索、通配符、目录扫描或“选择最像的一张”取得人物图。
3. **一人一 ID**：同一人物的姓名、乳名、职位、亲属称谓和说话人标签归一为一个稳定 `character_id`；不能确定时保留为未解决提及。
4. **一图一身份结论**：每个资产必须记录画面实际包含的人物、身份依据、用途和可用性。多人合照、故事板、带多个人物的资料卡不得作为单人身份锚。
5. **逐单元精确白名单**：每个出图单元只携带该单元可见人物的确认资产；多一个或少一个都阻断。
6. **不确定即阻断**：`probable`、视觉相似、命名推测或互相冲突的证据不能升级为确认。

## 工作流

### 1. 冻结脚本人物

完整扫描脚本，记录每一次人名、称谓、说话人和代词指向，保留精确 `source_ref`。建立人物登记表：

- `canonical_name`：脚本内最稳定、最可辨认的名称；
- `aliases`：只放在全剧中不会指向其他人的全局别名；
- `script_mentions`：逐条记录原文提及与归一结果；“妈妈”“老板”等可能换人的称谓必须按上下文逐条绑定，不能作为全局别名；
- `reference_policy`：可见固定人物为 `required`，无固定身份的群众为 `not_required`，纯画外音为 `forbidden`。

不得合并长相相似但剧情身份不同的人物，也不得把同一人物在不同年龄、伪装或换装状态误拆成不同身份；这些变化应作为该人物的 `variant_id` 或资产用途记录。

### 2. 清点并目视核验资产

递归列出候选图片，保留精确相对/绝对路径。可先运行：

```powershell
py scripts/inventory_character_assets.py <资产目录> --output <asset-inventory.json>
```

清单只负责发现文件、尺寸、哈希和完全重复图，不负责认人。随后实际查看每张候选图，记录：

- 画面人数与可见身份特征；
- 资产用途，如 `face`、`full_body`、`turnaround`、`costume`、`expression`、`multi_view`；
- 是否为干净单人参考图，是否有遮挡、低清、拼板、旧造型或身份漂移；
- 身份证据及来源。

只有用户明确确认、已批准人物档案/角色设定表的直接关联，或其他同等强度且可追溯的证据，才能记为 `confirmed`。仅凭文件名、文件夹名、生成时间或“看起来像”均记为 `unconfirmed`。

### 3. 建立唯一关联

为每张在审核范围内的图片分配稳定 `asset_id`，建立：

```text
script_mention -> character_id -> asset_id -> exact_path
```

检查并阻断：

- 一个别名映射到多个固定人物；
- 一张单人资产映射到多个人物；
- 完全相同的图片哈希被分配给不同人物；
- 同一人物的多张图出现脸型、年龄、性别呈现、发型、服装或关键配饰冲突，却没有已确认的变体说明；
- 资产库中存在疑似人物图但无人认领，或脚本人物没有合格资产。

不要擅自重命名用户文件。用清单解决异名；若用户另行要求整理命名，再单独执行可回退的重命名工作。

### 4. 逐出图单元做集合核对

从该单元的画面事实提取 `expected_character_ids`，只包含实际可见人物；纯台词提及、回忆中未出现者和画外音不得混入。然后生成：

- `character_asset_map`：每个需要固定参考的人物对应一个或多个确认资产 ID；
- `allowed_asset_ids`：上述映射值的无重复并集；
- `excluded_asset_ids`：审核范围内其余人物资产；
- `exact_paths`：白名单资产的精确路径。

必须满足：

```text
白名单人物集合 == 本单元需要固定参考的可见人物集合
allowed_asset_ids == character_asset_map 全部资产 ID 的并集
```

提示词使用 `character_id + canonical_name + asset_id + exact_path + asset_role` 明确绑定“谁使用哪张图”。禁止把整个资产目录作为参考输入。

### 5. 执行硬门校验

按 [审核数据规范](references/audit-schema.md) 保存 `character_asset_audit.json`，再运行：

```powershell
py scripts/validate_character_asset_audit.py <character_asset_audit.json>
```

仅脚本退出码为 `0` 且每个单元均为 `PASS` 时才可继续生图。退出码非零、字段缺失或仍需人工确认时停止生成，先交付阻断报告；不得用通用人物、首张搜索结果或无参考图临时补位。

## 人工确认门

以下情况必须向用户展示缩略图/路径、候选人物和冲突原因，请用户确认后更新审核文件并重新校验：

- 文件名与视觉身份或现有资产表互相矛盾；
- 两个人物外观高度相似或同一演员饰演多个身份；
- 同一称谓在不同场景指向不同人物；
- 只有视觉相似证据，无法获得权威关联；
- 资产是多人图、拼板、遮挡图或身份信息不足。

确认应针对明确的 `character_id <-> asset_id`，不能接受“应该是这个”“大概一致”作为放行依据。

## 交付物

每次审核至少交付：

1. `character_asset_audit.json`：机器可校验的完整关系与逐单元白名单；
2. `character_asset_audit.md`：人物、别名、资产、证据、冲突和单元状态的中文审阅表；
3. `generation_asset_packets/`：每个 `PASS` 单元一份只含允许人物资产精确路径的输入包；
4. 校验器输出或运行日志。

最终回复必须明确说明 `PASS/BLOCK`、脚本人物数、已确认资产数、被阻断单元及原因。`BLOCK` 时不得声称“已核对无误”或继续任何生图调用。
