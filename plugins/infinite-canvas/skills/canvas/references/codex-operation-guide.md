# Codex 画布操作教程

本教程说明 Codex 如何通过 Infinite Canvas 插件读取和操作用户当前连接的画布。它约束工具选择、节点定位、生成任务、短剧工作流和结果交付，不替代画布节点内的业务 Prompt 或内嵌 Skill。

## 1. 开始任务

1. 确认当前任务提供了 `infinite-canvas` MCP 工具。插件刚安装或更新后，需要新建 Codex 任务才能加载新的 Skill 和工具。
2. 用户尚未打开或连接画布时，使用 `open-canvas` Skill；不要让用户手动复制 Agent URL、token 或节点 JSON。
3. 用户要打开已有画布时，先用 `canvas_list_projects` 查找准确项目，再用 `site_navigate` 打开 `/canvas/<id>`。
4. 进入画布后先调用 `canvas_get_state`。如果用户说“这个”“当前节点”“选中的内容”，先调用 `canvas_get_selection`。
5. 如果工具报告没有已连接画布，停止写入并说明连接状态；不要改用鼠标模拟或猜测本地存储。

## 2. 事实来源与节点定位

- 当前 `canvas_get_state` 或 `canvas_get_selection` 返回的节点、连线、选区和生成状态是画布事实来源。
- 节点标题可能重复。读取、更新、连接、删除、引用和查询生成状态时一律使用准确 `nodeId`，不要按标题猜测。
- 写入后如果下一步依赖新节点 ID、自动创建的生成节点或最新连线，重新读取画布状态再继续。
- 不覆盖原始输入节点。新增处理结果时创建下游节点并连线，让来源可追溯。
- 用户指定在新画布测试时，不得写入原画布。先列出或创建目标画布并确认当前项目 ID。

## 3. 选择合适的工具

| 目的 | 优先工具 |
| --- | --- |
| 读取整个画布 | `canvas_get_state` |
| 读取用户当前选择 | `canvas_get_selection` |
| 查看布局快照 | `canvas_export_snapshot` |
| 创建单个或多个文本节点 | `canvas_create_text_node` / `canvas_create_text_nodes` |
| 创建图片、视频、配置、音频或分组占位 | `canvas_create_node` |
| 把本轮附件放入画布 | `canvas_create_attachment_nodes` |
| 更新文本正文 | `canvas_update_node_text` |
| 更新节点字段或业务元数据 | `canvas_update_node` |
| 移动、缩放、连接、选择节点 | 对应的 `canvas_move_nodes`、`canvas_resize_node`、`canvas_connect_nodes`、`canvas_select_nodes` |
| 一次完成多种节点和连线修改 | `canvas_apply_ops` |
| 创建可编辑但暂不执行的生成流程 | `canvas_create_generation_flow`，设置 `autoRun: false` |
| 立即生成文本、图片、视频或音频 | `canvas_generate_text` / `canvas_generate_image` / `canvas_generate_video` / `canvas_generate_audio` |
| 查询异步生成进度 | `generation_get_status` |

仅调用当前上下文真实提供的工具。若教程与当前工具定义不一致，以工具定义为准，不得编造参数。

## 4. 创建和整理节点

- 单个结果用单节点工具；同类批量文本优先一次创建，减少无意义的往返。
- 创建多节点流程时预留稳定间距，默认从左到右表示执行顺序，从上到下表示同一步的并行分支。
- `group` 用于表达场景或业务分组，不是大段结果的替代品。组内仍应保留可独立引用的节点。
- 连接方向始终是“事实来源或上游结果 → 使用它的下游节点”。
- 修改已有文本时只更新目标节点；不要通过创建同名节点伪装成编辑。
- 删除节点或连线前重新核对准确 ID。用户没有明确要求删除时，不清理可能仍有价值的节点。

需要批量操作时，先在一次 `canvas_apply_ops` 中完成同一原子步骤，例如创建节点、建立连线和选择最终节点；不要把无关步骤塞进一个大操作。

## 5. 生成流程

### 5.1 创建流程

- 用户要先检查 Prompt 或参数：使用 `canvas_create_generation_flow`，保持 `autoRun: false`。
- 用户明确要求“出图”“生成视频”“开始生成”：使用对应的 `canvas_generate_*`，让画布创建原生配置节点和媒体结果节点。
- 生成必须使用画布原生生成能力。不要在画布外生成文件后伪装成画布生成结果。
- 人物、场景、道具、上一张确认图等参考素材都通过准确的 `referenceNodeIds` 传入，并建立真实输入连线。
- Prompt 只引用现有节点时，使用 `@[node:<nodeId>]` 和相同的 `referenceNodeIds`，避免重复创建内容相同的 Prompt 节点。

### 5.2 查询和停止条件

1. 提交后记录工具返回的配置节点、结果节点或任务 ID。
2. 使用 `generation_get_status` 按返回 ID 查询；一次只查询当前批次。
3. 任一节点仍为排队或生成中时，不得重复提交同一请求。
4. 全部节点进入成功、失败或取消等终态后再汇报本批结果。
5. 部分失败时报告准确节点 ID 和错误。除非用户明确要求重试，或者工具明确证明请求从未提交到远端，否则不得自动重发可能产生费用的生成任务。
6. 用户要求固定数量时，成功结果和终态失败结果的总数必须与请求数量对应；不得用一个成功节点冒充整批完成。

## 6. 提示词中心和内嵌 Skill

- 提示词中心是受管理业务 Skill 的唯一编辑入口。不要直接修改 Agent 面板中的只读副本。
- 工作流输入画布后，节点 `workflowEmbeddedSkill.instructions` 是该次画布执行的权威 Skill 正文。
- 执行内嵌工作流时，不得用本机 `.codex/skills`、`.agents/skills` 或同名 `$skill-name` 覆盖节点快照。
- 只在用户回到提示词中心保存新版本并同步到画布后，后续执行才使用新正文。
- 工作流卡片的排列顺序是执行顺序，但仍须检查上游输出是否满足下游输入；缺少必需输入时只阻断相关分支并写明原因。

## 7. 短剧工作流

### 7.1 原始输入落盘到画布

- 用户提供文件时，先把完整原文放进可见的输入节点，并保留文件名、工作表/页码、行列或段落位置等来源信息。
- 输入节点只有文件路径、摘要或截断内容时，不启动第一个业务 Skill。
- 后续步骤不得覆盖或缩短原始输入节点。

### 7.2 脚本转化布局

- 按 `SCENE` 创建独立 `group`。
- 按 `VID` 创建完整独立文本节点，放入对应 SCENE；不要把所有 VID 堆在一个文本节点。
- 转化步骤的主节点完成后只保存进度、数量和有序索引，不保存替代全部 VID 的大段正文。

### 7.3 逐 VID 执行和溯源

- 脚本转化后的每一个 Skill 都按 VID 独立执行，不把全部文本一次丢给下游。
- 每个输出直接连接它实际使用的上游节点，并保存：
  - `workflowSourceNodeId`
  - `workflowSourceVidId`
  - `workflowSceneId`
  - `workflowSkill`
  - `workflowStep`
  - `workflowBranchStatus`
- 一个 VID 失败或缺少资产时只阻断该分支，不影响其他 VID。
- 每个 Skill 的主节点完成后转为索引节点，连接本步骤全部 VID 输出；最终输出节点也只保存索引和状态。

### 7.4 关键帧和视频

- 生图 Prompt 节点、画布原生生成配置节点和图片结果节点必须分开并真实连线。
- 人物资产先经过唯一身份关联审核；文件名不能代替人物身份判断。
- 同一人物跨帧生成时，每一帧都绑定权威人物资产，并把上一张一致性校验通过的确认图作为下一张身份参考。
- 每帧检查人物集合、脸部结构、发型、体型、已确认服装变体和关键配饰。漂移时阻断当前 VID 分支。
- 负面提示词只写当前画面的少量明确风险，不堆叠通用负面描述。
- 视频提示词必须连接对应 VID 的已确认关键帧、生图 Prompt、人物与场景资产，不能从其他 VID 借用看似相似的结果。

## 8. 完成任务时

- 选中本轮最重要的结果或索引节点，必要时调整视口让用户打开画布即可看到。
- 汇报写入的画布名称、成功节点数量、失败或阻断节点及下一步，不要只说“完成了”。
- 生成任务仍在运行时明确说“已提交，尚未完成”，不要提前宣称生成成功。
- 不在节点正文、日志或回复中暴露 API Key、Agent token 或其他凭据。

## 9. 常见请求的执行方式

- “把这段文字放到画布”：读取状态 → 创建文本节点 → 选中新节点。
- “根据选中的图出视频”：读取选区 → 核对准确图片节点 → 创建视频生成流程并绑定参考 → 查询终态。
- “把所有 VID 往下跑”：读取全部 VID 和工作流顺序 → 按 VID 建立独立分支 → 逐步写入来源元数据 → 每步生成索引。
- “重试失败的图”：读取失败节点与状态 → 仅重试用户指定的失败节点 → 不动成功节点。
- “在原画布继续”：先核对当前画布项目 ID → 从现有终点向后追加节点 → 不复制或重建已确认结果。
